# 网页版（在验证阶段）

这个目录现在只做一件事：**验证 iOS 上「添加到主屏幕」的网页应用，长期不用会不会丢数据。**

结论决定网页版能不能做：

- **数据不丢** → 网页版可行，继续往下开发（数学层、地图、界面）
- **数据会丢** → 必须改成"每次打开自动同步到服务端"，那就需要后端，复杂度完全不同

## 为什么先验这一条

iOS Safari 明确实现了「7 天不用就清空脚本可写存储」的策略
（[WebKit #209501](https://wiki.webkit.org/show_bug.cgi?id=209501)）。

WebKit 同时表示**「添加到主屏幕」的 Web App 不应被清**，但有几个 bug 报告显示
豁免在某些版本上没生效（[#237350](https://wiki.webkit.org/show_bug.cgi?id=237350)、
[#232302](https://wiki.webkit.org/show_bug.cgi?id=232302)）。

**这件事无法靠读文档确定，只能实测。**

## 怎么跑测试

### 1. 启动开发服务器

```powershell
node web/serve.js 8099
```

启动后会打印本机和局域网地址。

### 2. 让朋友用 iPhone 打开

★ **必须同一个 WiFi。** 手机上打开：

```
http://<你电脑的局域网IP>:8099/
```

（IP 在服务器启动时已经打印出来了，例如 `http://192.168.0.219:8099/`）

★ **不要用微信内置浏览器打开** —— 它不支持「添加到主屏幕」，测试没有意义。

### 3. 朋友要做的三步（页面上也写着）

| 步骤 | 操作 |
|---|---|
| 1 | 在 Safari 里打开上面的链接，按页面上的「**开始测试**」按钮 |
| 2 | 分享 → **添加到主屏幕** → 添加 |
| 3 | **从桌面图标打开一次**确认能看到结果，然后 **7 天内完全不要打开** |

### 4. 第 8 天

从桌面图标打开，页面上会显示「**数据存活**」或「尚未开始」（后者说明被清了）。

**让朋友截图发你**，或者在有网时点「上报结果到服务器」。

## 怎么读结果

### 手机上直接看

页面会显示一个明确结论：

- **数据存活** —— 停靠 7 天以上数据仍在
- **尚未开始** —— 数据被清掉了（说明这条路走不通）

### 服务端记录

```powershell
# 汇总
curl http://localhost:8099/api/checkins

# 原始记录
type web\checkins\checkins.jsonl
```

服务端日志的意义：**即使手机本地被清空，我也能从服务端看到"它曾经来过"**。
只有本地日志的话，被清之后什么都查不到，无法判断是"没来过"还是"来过但被清了"。

记录里几个关键字段：

| 字段 | 含义 |
|---|---|
| `markerExists` | 本地数据是否还在 |
| `daysSinceFirst` | 距首次写入过了几天 |
| `standalone` | 是否从主屏幕图标打开（**必须为 true 测试才有效**） |
| `iosVersion` | iOS 版本（判断豁免策略是否受版本影响） |
| `recordCount` | IndexedDB 里的记录条数（心跳次数 ≈ 打开过几次） |
| `persisted` | `navigator.storage.persisted()` 的结果 |

## 已知约束

### GPS 需要 HTTPS

浏览器的 `geolocation` 只在安全上下文（`https://` 或 `localhost`）可用。
`http://192.168.x.x` 不是安全上下文，**手机上的定位按钮会失效**。

- **存储测试不受影响**（不发定位）
- **正式给朋友用时必须走 HTTPS** —— 最省事的是 GitHub Pages（免费、自带 HTTPS）

### 开发调试时的坑

**headless 浏览器里 `indexedDB.open()` 永不回调。**

我在 Edge headless 里验证时卡了很久：页面静态部分正常、脚本也执行了，
但所有异步逻辑静默挂住，看不出任何错误。原因是 headless 环境的 IndexedDB 不可用
（`open()` 既不成功也不失败，只是不回调）。

**真实浏览器里完全正常**（实测：打开、写入、读取全部成功，配额 10 GB）。

所以：**验证网页逻辑要用真实浏览器窗口，不要用 headless。**

页面里留了两个调试信标，正是为了区分"脚本没跑"和"脚本跑了但卡住"：

| DOM 属性 | 含义 |
|---|---|
| `data-js="started"` | 脚本已开始执行 |
| `data-init="…"` | 初始化流程走到哪一步 |
| `data-stage="…"` | `checkTest()` 内部走到哪一步 |

查看方式：DevTools 里看 `<html>` 元素，或 `--dump-dom` 后 grep。

```
步骤 2  数学层搬成 JS，接同一份 testdata/vectors.json
        CoordinateTransform + SunMoon + GeoViewport → 纯函数
        Node 里直接跑契约测试（无需任何环境配置，比 Swift 那套省事）

步骤 3  Canvas 重画地图
        HTML Canvas 与 Android Canvas API 几乎一一对应
        底图直接用现有的 assets/basemap_*.txt

步骤 4  界面 + 离线缓存（Service Worker）

步骤 5  Android 侧加 WebView 外壳 + 原生导出通道（可选）
```

## 与原生 Android 版的关系

**网页版是试验田，不是替代品。** 两者定位不同：

| | 原生 Android | 网页版 |
|---|---|---|
| GPS（息屏/后台） | ✅ | ⚠️ 仅前台 |
| 文件导出 | ✅ 任意位置 | ⚠️ 下载目录 |
| 离线可靠性 | ✅ | ⚠️ 依赖缓存 |
| 分享给朋友 | ❌ | ✅ 一个链接 |
| 迭代速度 | 慢（adb/dump） | 快（DevTools） |

钓鱼场景需要"水库边没信号 + 长时间定位"，这两点上原生更可靠 —— 所以原生版继续作为主力。
