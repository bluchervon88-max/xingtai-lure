## 二、为什么这条路能绕开 Mac

```
① 编译          GitHub Actions 的 macOS runner（公开仓库免费、不限时长）
                产物：未签名的 IPA          ← 已完成
                     ↓
② 签名 + 安装    SideStore（装在 iPhone 上，用你的免费 Apple ID）
                     ↓
③ 续签          SideStore 后台自动完成，之后不需要再碰电脑
```

免费 Apple ID 的限制：**同时最多 3 个 App**（含 SideStore 自己）、
**一周最多 10 个新 App ID**。自用足够。

## 三、你需要做的

### 第 1 步：装 SideStore（一次性）

按官方文档操作：<https://docs.sidestore.io/docs/installation/prerequisites>

要点：
- **只有安装阶段需要电脑**（Windows 也行），之后就不需要了
- 用一个**专门的小号 Apple ID**，不要用主力账号
  （第三方签名工具都有触发 Apple 账号风控的可能，官方 FAQ 也提到了这点）
- 装完先**刷新一次 SideStore 自己**（官方 FAQ 有说明原因）

### 第 2 步：把 IPA 传到手机

任选一种：
- 用微信 / QQ 发给自己，在手机上存到「文件」App
- 用网盘
- 数据线拷贝到「文件」App

### 第 3 步：安装

在 iPhone 上打开「文件」App，找到那个 `.ipa`，**用 SideStore 打开它**
（长按 → 共享 → SideStore；或直接在 SideStore 里选「从文件安装」）。

### 第 4 步：装好后先做一件事 —— 导出诊断

**这一步很重要，因为我（开发者）看不见你的屏幕。**

App 里有一个「诊断」按钮。点它会：

1. 把**视图层级和实测尺寸**写成文件
2. 文件位置：`「文件」App → 我的 iPhone → XtLure → layout-dump.txt`

**把这个文件发给我**，我就能"看见"界面了。

也可以直接点「诊断」按钮然后截图，但文件信息更全
（里面有每个控件的实际像素尺寸、以及"有内容但尺寸为 0 的隐形控件"清单）。

### 第 5 步：告诉我结果

- 能正常启动吗？
- 首屏显示的是什么内容？
- 诊断文件里那几行环境信息（机型、系统版本、屏幕尺寸、安全区）

## 六、⚠️ 网络问题：推送 GitHub 可能需要代理

**遇到的实际情况**：首次推送成功后，后续推送开始持续失败：

```
fatal: unable to access '...': Recv failure: Connection was reset
```

诊断结果（`github.com:443` 被针对性阻断，其他 GitHub 域名都正常）：

| 端点 | 连通性 |
|---|---|
| `api.github.com:443` | ✅ 通 |
| `github.com:22`（SSH） | ✅ 通 |
| `ssh.github.com:443` | ✅ 通 |
| `codeload.github.com:443` | ✅ 通 |
| **`github.com:443`** | ❌ **超时** |

系统里本来就有本地代理（`127.0.0.1:7892`），配上就能推：

```powershell
git config --global http.https://github.com.proxy http://127.0.0.1:7892
```

**如果以后推送又失败**，先按这个查：

```powershell
# 1. 代理端口在监听吗
Get-NetTCPConnection -LocalPort 7892 -State Listen

# 2. 代理能通吗
Invoke-WebRequest -Uri 'https://github.com' -Proxy 'http://127.0.0.1:7892' -Method Head

# 3. 取消代理配置（如果不再需要）
git config --global --unset http.https://github.com.proxy
```

## 七、已知限制

| 限制 | 说明 | 能否解决 |
|---|---|---|
| 7 天过期 | 免费签名只能维持 7 天 | ✅ SideStore 后台自动续签 |
| 同时 3 个 App | 免费 Apple ID 的限制，含 SideStore 自己 | ❌ 除非买 $99/年 |
| 一周 10 个 App ID | 装太多新 App 会触发 | ⚠️ 正常开发碰不到 |
| **没有图标** | 用的是系统默认图标 | ⏳ 待做（原因见下） |
| **界面很素** | 第一版是验证版 | ⏳ 待做 |
| **UI 迭代慢** | 我看不见界面，每轮要你导诊断或截图 | ⚠️ 靠内置诊断减轻 |

### 关于图标

iOS 版现在**没有自定义图标**。安卓版用的是从 `dsh-whale-widget` 插件取的素材，
但那个插件的 `PROVENANCE.md` 明确写着：`assets/**` 不适用 MIT、
**不授予再许可**、来源为不可考的 AI 生成图。

安卓版是你自己的判断，我按你的决定执行了。
但 **iOS 这边是要推到公开 GitHub 仓库的**，性质不一样，所以我没有把那个素材带进来。

想加图标的话，`tools/make-icon-fish.py`（原创小胖鱼）那条路还在 ——
iOS 的图标规格我可以另写一个生成脚本（需要各尺寸 PNG + Contents.json）。

## 八、目录结构

```
ios/
  XtLure.xcodeproj/
    project.pbxproj                手写的工程文件（Windows 上没法用 Xcode 建）
    xcshareddata/xcschemes/        CI 靠它找到构建目标
  XtLure/
    AppDelegate.swift              入口 + 全局崩溃捕获
    SceneDelegate.swift            窗口
    MainViewController.swift       主界面（第一版是验证版）
    Diagnostics.swift              ★ 诊断模块，替代 adb 的界面 dump
    Palette.swift                  配色（与安卓版一致）
    Info.plist                     含文件共享开关（诊断导出靠它）
    Resources/                     spots_seed.json + 三个 basemap 数据
    Core/                          ← 生成物，由 sync-sources.js 同步
  Sources/
    XtLureCore/                    ★ 逻辑层单一来源（能在 Windows 上编译测试）
    VectorTest/                    跨语言契约测试
  sync-sources.js                  同步 + 清单一致性检查
  add-to-project.js                往 pbxproj 登记新文件（四处一次写全）
  swift-test.ps1                   Windows 上跑契约测试

.github/workflows/build-ios.yml    构建未签名 IPA
tools/validate-pbxproj.py          工程文件结构校验 + 漏登记检查
tools/check-callsites.py           UI 代码对核心 API 的调用点校验
tools/compute-basemap-truth.py     独立算出底图真值
```

### 为什么源码有两个位置

| 位置 | 用途 |
|---|---|
| `Sources/XtLureCore/` | **单一来源**。不依赖 UIKit，能在 Windows 上用 swiftc 编译和测试 |
| `XtLure/Core/` | **生成物**。Xcode 工程按固定相对路径找文件 |

**只改 `XtLureCore`**，然后跑 `node ios/sync-sources.js`。
CI 会检查两边是否一致 —— 不一致直接构建失败。
